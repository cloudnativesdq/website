# Design

## Context

- The App Router lives in `src/app/`, so Next.js metadata file conventions go there (`src/app/icon.svg`, `src/app/favicon.ico`, `src/app/apple-icon.png`, `src/app/manifest.ts`). The installed version is Next 16.4.1. Its docs (`node_modules/next/dist/docs/.../01-metadata/app-icons.md`, `manifest.md`) confirm: `favicon` is `.ico` only and only in the root segment, `icon` accepts `.svg`, `apple-icon` accepts `.png`, and the head tags are generated from the files. A static file gets `sizes="any"` when it is SVG.
- `src/app/layout.tsx` declares `icons` pointing at `public/favicon.svg` (an unrelated Azure-blue placeholder). Static file conventions and the `icons` field would both emit tags, so the field must go.
- `src/lib/links.ts` points three things at the files being deleted: `siteLogo` (`/favicon.svg`, used as the Organization logo and as the event image fallback in the home JSON-LD) and `eventFallbackImage` / `organizerFallbackImage` (`/images/logo.png`, used by `EventCard` and `OrganizersSection` through `next/image`).
- Navbar (`Navbar.tsx:137-139`) and footer (`Footer.tsx:51-53`) render "Cloud Native SDQ" as two text spans. The footer copyright line also says "Cloud Native SDQ"; it is text, not the lockup, and stays.
- Tokens: `globals.css` holds shadcn HSL triplets (comment: "change a color in the design system, not here"), and `_ds/style-guide/tokens/colors.css` holds the hex source. Today the dark `--primary-foreground` in `globals.css` is already a dark ink (`200 82% 9%` = `#041d2a`) while the design-system `--text-on-accent` is `#ffffff`; the two disagree. The light theme uses `#0284c7` in `--primary`, `--accent`, `--ring`, `--sidebar-primary`, `--sidebar-ring`, and the design system also derives `--accent-soft`, `--border-accent` and `--glow` from it.
- `_ds/style-guide` is a git submodule. Its readme, `ATTRIBUTION.md`, `github.md` and `guidelines/brand-logo.card.html` say no logo exists, and `assets/favicon.svg` is a copy of the placeholder.
- `sharp` 0.35.5 is allowed to build (`pnpm-workspace.yaml`), but it is not listed in `package.json`; it arrives only through `next` (`node_modules/.pnpm/sharp@0.35.5_*`). `node_modules/sharp` is a stale 0.34.5 directory from May that pnpm does not manage (`publicHoistPattern: []`), so a bare `import 'sharp'` today resolves to the wrong copy by accident.

## Goals / Non-Goals

**Goals:**
- One SVG source; every raster regenerated by one command.
- Icon tags produced by Next file conventions, not hand-written metadata.

**Non-Goals:**
- Open Graph images (change `social-preview-images`) and JSON-LD rewrites (change `seo-metadata-fixes`). This change only repoints `links.siteLogo` because it deletes the file that link targets.
- Redrawing the mark. The approved SVG is committed as delivered.
- Generating icons at build time.

## Decisions

**Asset layout.** Brand files live in `public/brand/`: `mark.svg` (source, copied verbatim from `openspec/changes/brand-identity-assets/inputs/mark.svg`), `mark-mono.svg`, `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`. The file-convention copies `src/app/icon.svg`, `src/app/favicon.ico` and `src/app/apple-icon.png` are written by the same script. `src/app/icon.svg` duplicates `public/brand/mark.svg` because Next only reads icon files from `app/`. The script keeps them identical. Alternative: `icon.tsx` generating from code. Rejected because a static SVG is smaller and cacheable with no route handler.

**One-color variant.** Same paths as `mark.svg` with every `stroke`/`fill` set to `currentColor`. The light-cyan swell and the dot lose their distinction, so the swell keeps a reduced stroke opacity (0.6) to stay readable as a second shape. The variant is for single-ink surfaces (print, embossing, future use in OG images); this change does not render it on the site.

**Generation script.** `scripts/generate-brand-icons.mjs`, exposed as `pnpm brand:icons`. Outputs are committed; the build never runs it. `sharp` is listed in `dependencies` at exactly `0.35.5`, the version `next` already pins, so pnpm links the existing package and replaces the stale top-level copy. The user chose this over loading next's copy through `createRequire`, which was indirect and would break if `next` dropped sharp. It goes in `dependencies`, not `devDependencies`, because `social-preview-images` uses it in a route. Keep it in step with `next`'s range on upgrades.

- `icon-192.png`, `icon-512.png`: mark on transparent background with 8% padding (purpose `any`). `icon-512.png` doubles as the JSON-LD Organization logo and the image fallback.
- `icon-maskable-512.png`: opaque `#090d16`, mark scaled so its bounding box fits inside a centered circle of 80% diameter. The mark is nearly square, so a box of about 56% of the icon width fits (diagonal ≈ 0.79 × 512). The script asserts this geometry instead of eyeballing it.
- `apple-icon.png`: 180x180, opaque `#090d16`, mark at about 70% width, flattened so no pixel is transparent (iOS fills transparency with black).
- `favicon.ico`: sharp cannot write ICO, so the script renders 16, 32 and 48 PNGs and packs them into an ICO container (6-byte header, 16-byte directory entry per image, PNG payloads). This takes about 20 lines and needs no library. At 16px the mark is rendered directly from the SVG, with no hand-tuned pixel version: `mark-preview.png` shows the curl and dot still read at 16px.

**Lockup component.** New `src/components/BrandLockup.tsx` renders the mark as inline SVG (`aria-hidden`) followed by the text "Cloud Native Santo Domingo" in `font-heading font-bold` (Space Grotesk 700 is already self-hosted). Inline SVG avoids an extra request and layout shift. Navbar and footer wrap it in their existing `<Link href="/">`, so the link's accessible name is the text. At narrow widths the text breaks onto two lines ("Cloud Native" / "Santo Domingo") with tight leading instead of truncating; the mark keeps a fixed size. The mark stays full color in the light theme. The cyan measures 2.71:1 on white, but logos are exempt from WCAG contrast rules, and the dark navbar is the default theme.

**theme-color.** `export const viewport: Viewport = { themeColor: [{ media: '(prefers-color-scheme: dark)', color: '#090d16' }, { media: '(prefers-color-scheme: light)', color: '#f7f9fc' }] }` in `layout.tsx`. It follows the OS scheme, not the in-page theme toggle; matching the toggle would need client JS and is not worth it.

**Manifest.** `src/app/manifest.ts` returns name "Cloud Native Santo Domingo", short_name "CN SDQ", `start_url: '/'`, `display: 'standalone'`, `background_color` and `theme_color` `#090d16`, and the three PNG icons from `public/brand/`.

**Token values.**

| Token | Theme | Old | New | Ratio |
|---|---|---|---|---|
| `--text-on-accent` (ds), `--primary-foreground`, `--accent-foreground`, `--sidebar-primary-foreground` (site) | dark | `#ffffff` (ds) / `#041d2a` (site) | `#04202f` = `200.9 84.3% 10%` | 6.20:1 on `#0ea8e6` |
| `--accent` (ds), `--primary`, `--accent`, `--ring`, `--sidebar-primary`, `--sidebar-ring` (site) | light | `#0284c7` = `200.4 98% 39.4%` | `#0369a1` = `201.3 96.3% 32.2%` | 5.93:1 white on accent; 5.63:1 as text on `#f7f9fc` |
| `--accent-hover` (ds) | light | `#0369a1` | `#075985` | 7.56:1 white |
| `--accent-soft`, `--border-accent`, `--glow` (ds) | light | from `#0284c7` | same alpha, from `#0369a1` (`rgba(3,105,161,…)`) | n/a |

The design system is the source. Edit `colors.css` first, then mirror the triplets in `globals.css` and update their hex comments.

**Fallback images.** `EventCard` renders `object-cover` in a box that is full width × `h-48` on phones, `sm:w-48` on desktop, and a square `w-28`/`w-32` when compact. A square transparent icon would be sliced in the wide box. So the script also writes `public/brand/event-placeholder.png`: 1200x800, opaque `#090d16`, mark at about 22% of the width, centered. At any cover crop between 16:9 and 1:1 the mark stays inside the visible center. The script asserts this the same way it checks the maskable icon. `links.eventFallbackImage` becomes `/brand/event-placeholder.png`. `links.organizerFallbackImage` becomes `/brand/icon-512.png`, which works because the avatar box is square. `links.siteLogo` becomes `https://cloudnativesdq.org/brand/icon-512.png`. PNG keeps `next/image` working without `dangerouslyAllowSVG`. Alternative: switch the fallback to `object-contain`. Rejected because it needs a per-image class swap in two components for a case a single asset solves.

**Naming.** "Cloud Native Santo Domingo" on every visible surface. "Cloud Native SDQ" stays only as the schema.org `alternateName` (fixed from the "CNCD SDQ" typo in `seo-metadata-fixes`). "CN SDQ" is the manifest `short_name`, because Android launchers truncate after about 12 characters. Code edits in this change: footer copyright (`Footer.tsx:105`) and the email `from` display name (`send-email.ts`, the display part only; the address stays `notificaciones@cloudnativesdq.org`).

**404, error page, skip link.**
- `src/app/not-found.tsx` becomes a server component that exports `metadata` (`title: 'Página no encontrada | Cloud Native Santo Domingo'`, `robots: { index: false }`) and renders a small client `NotFoundView`: `Navbar`, a `<main id="main">` with `t.notFound.title`/`t.notFound.body`/`t.notFound.home`, then `Footer`. The `usePathname` + `console.error` effect is deleted.
- `src/app/error.tsx` (required to be a client component) uses the same shell, with `t.error.*` and a "Reintentar" button calling `reset()`. Strings go in `translations.ts` for both `es` and `en`.
- Skip link: first child of `Navbar`, `<a href="#main" className="sr-only focus:not-sr-only …">` with `t.nav.skipToContent`. Every page view gets `id="main"` on its `<main>`. They are the existing `*View`/`*Page` components, so it is one attribute per file.

## Risks / Trade-offs

- [External sites hot-link `/favicon.svg` or `/images/logo.png`] → Accepted. The spec requires 404. A redirect would keep serving the old placeholder identity.
- [16px favicon from an unhinted SVG may blur] → Mitigated by the preview at 16px. If it reads poorly in real tabs, add a hand-tuned 16px SVG later without changing the spec.
- [The lockup is longer than the old wordmark and may crowd the mobile navbar] → The existing e2e overflow test runs on Pixel 7, and a manual check at 360px is a task.
- [The submodule edit can be forgotten when this repo is committed] → A task covers committing in `_ds/style-guide` and bumping the pointer.
- [Darker light accent changes the feel of light-theme links and buttons] → Intended. The contrast fix is the point.

## Migration Plan

Ship as one PR. Rollback = revert the PR. The submodule pointer reverts with it. No data migration.
